# Product Direction

## Positioning

Desto 是一个简约、快速且长期常驻的 Windows 桌面整理工具。它帮助用户在一个或多个显示器上建立可控的桌面区域，并将项目按自己的方式组织、展示和访问。

Desto 不以提供最多的盒子类型或最多的视觉效果为目标。核心体验必须先达到稳定、快速、可预测，再扩展能力。

## Core Concepts

### Container

`Container` 是产品内部对“收纳盒”的稳定称呼，最终展示给用户的名称可以以后再确定。

所有 Container 共享：

- 稳定身份。
- 所属工作区和显示器布局。
- 位置、尺寸、可见性与生命周期。
- 支持的能力集合。
- 实例级功能入口配置。
- 实例级外观配置。

具体 Container 类型在此基础上扩展自己的内容和行为。

### Capability

能力表示 Container 可以做什么，例如展开、收起或提供某种内容视图。能力存在，不代表对应入口必须始终显示。

能力、入口和表现必须分离：

- 能力决定是否支持该行为。
- 实例偏好决定是否在 Container 上显示入口。
- 外观决定入口和 Container 如何呈现。

因此，用户可以保留某项能力，同时按单个 Container 隐藏自己不需要的按钮或装饰。

### Appearance

外观属于 Container 实例，而不是 Container 类型的固定副作用。类型可以提供默认外观，但每个实例可以独立覆盖。

外观配置应当描述用户可理解的视觉属性，不应暴露渲染器内部实现。

### Workspace And Display

布局从第一版开始支持多个显示器。显示器是工作区的投影目标，而不是简单的数组序号。

产品需要支持：

- 每个显示器独立布局。
- 跨显示器的统一虚拟布局。
- 将一组布局映射到一个或多个显示器。
- 显示器断开后的安全回退，以及重新连接后的恢复。

具体交互和映射方式将在功能设计中确定。

## Product Principles

- 默认体验保持简洁，不把所有能力都堆在 Container 表面。
- 有实际个人偏好的内容应允许按实例配置。
- 全局设置用于快速建立默认值，实例设置用于表达用户明确意图。
- 用户关闭视觉入口或功能后，界面和资源占用都应真实反映该选择。
- 高级能力不应增加基础使用路径的理解成本。

## Initial Non-goals

以下内容在基础架构稳定前不进入核心范围：

- 账号体系和云同步。
- 在线社区、模板市场和插件市场。
- 与桌面整理无关的综合效率功能。
- 为兼容所有平台而牺牲 Windows 原生体验。
