# Application Card

## Ownership

Application Card 管理存储根下自己的相对目录。Explorer 拖入的文件或目录会被移动到该目录，而不是只保存外部路径。导入使用文件事务；同批任一移动失败时回滚已经完成的移动。

重名项目保留原扩展名并依次使用 `Name (1)`、`Name (2)`。已经位于 Card 目录内的项目不会重复移动，包含 Card 存储目录的上级目录不能被拖入，避免递归复制或移动自身。

## Shell Presentation

Windows Adapter 枚举 Card 目录并生成不可变项目视图：

- 普通文件和目录使用真实文件名（包含扩展名）与真实 Shell 图标。
- `.lnk` 标题忽略扩展名，并解析目标路径。
- 商店应用快捷方式读取 `PKEY_AppUserModel_ID`；图标优先从 `shell:AppsFolder` 的真实应用项提取。
- 缺失项目、不可解析快捷方式和图标不可用是不同状态。
- 图标不可用时不绘制 `FILE`、字母块或其他伪造图标；名称仍保留，项目仍可在可启动时打开。

默认不在图标下方显示文件名。项目槽位在鼠标悬停时显示轻量热点，停留约 600 ms 后显示文件名 Tooltip；失效项目追加简短状态，不显示完整文件路径。双击通过 Windows Shell 打开原始项目。

Grid 和 List 中的实际项目均支持右键。宿主从项目绝对路径解析 PIDL，通过父 `IShellFolder` 请求 `IContextMenu`，Open/Cut/Copy/Delete/Properties 等命令由该文件自己的 Shell handler 执行；文件项重命名入口已从 Desto 菜单移除。Windows 11 build 22000 及以上且未检测到经典菜单覆盖时，先显示实际存在的紧凑核心动词，并提供“显示更多选项”进入完整菜单；旧系统或 `HKCU\\Software\\Classes\\CLSID\\{86ca1aa0-34aa-4e8b-a509-50c905bae2a2}\\InprocServer32` 覆盖存在时直接显示完整 `IContextMenu`，owner-draw 消息交给 `IContextMenu2/3`。Explorer 的 Win11 XAML 菜单没有公开的任意 HWND 托管 API，因此紧凑层使用系统主题 `HMENU`，不伪称复用了 Explorer 内部 XAML 控件。空白区域不弹出文件菜单，展示模式切换不改变右键所指向的原始路径。文件夹的 Open 始终交给资源管理器打开。

文件项不提供重命名入口；需要改名时通过资源管理器打开文件夹后使用 Windows 原生操作。

图标提供小、中、大、特大四档，默认大图标；显示尺寸依次为 20、26、34、44 DIP，网格步长依次为 37、44、55、74 DIP，不在步长之外重复增加间距。为避免高 DPI 下放大 16/32 px 位图，四档分别向 Shell 请求 32、48、64、96 px 的常见原生帧，再由宿主单次高质量缩小到物理显示尺寸。每个项目只保留当前 Card 所需的一份源图，不为四档同时缓存。所有可点击图标都必须提供轻量 hover 热点和更明确的 pressed 反馈；当前项目图标和收缩 Chevron 使用同一交互规则。

宿主使用预乘 Alpha 双线性采样缩放 Shell 图标，避免最近邻台阶和低分辨率放大造成的模糊。实例切换任一档位时重新解析对应原生源帧，并把项目、偏好和尺寸作为一批离屏画面提交。

## Drag And Ordering

宿主使用 OLE `IDropTarget` 接收 Explorer 的 `CF_HDROP`，在 `DragOver` 阶段把卡片内容区内的任意指针位置连续映射到最近槽位；图标间距和左右留白不是禁止区。预选使用轻填充和 2 DIP 对称圆角虚线框标出真实落点，只有槽位变化时才重绘；空 Card 使用同一描边实现，避免 Win32 1 px 虚线在不同边缘出现粗细不一。固定格数已满时才拒绝拖入。

自适应模式以 `widthSpan=4` 在当前图标档位的投影列数为基线；自定义布局再与最右占用槽位取较大值，而不是让历史 widthSpan 或项目数量无条件撑宽。指针到达水平外缘时预览新增一列，到达下侧外缘时新增一行；首次边缘扩展等待 200 ms。右对齐 Placement 保持右边缘并向左扩展，每次连续左扩额外增加 300 ms 阻尼且不设上限；Left 保持左边缘并向右扩展。收缩每次最多一列，离开当前列区域后等待 200 ms，期间重新进入会取消。高度始终保持顶部并向下增长。拖放预览参与临时内容边界；由窗口扩张产生的 OLE `DragLeave/DragEnter` 抖动使用 90 ms 延迟清理吸收。固定格数不参与自动扩缩。

Drop 在文件移动前完成 Shell 元数据准备并持有每张 Application Card 的内存项目快照。文件事务成功后只更新路径、纯内存布局和离屏画面，不再同步重新枚举目录或解析图标；成功提交后同时写入标准 OLE `Performed DropEffect` 并发送 Shell 移动/目录变更通知，使 Explorer 及时移除源项目。Desto 内部 Drop 另写完成标记，源卡的 `DoDragDrop` 返回后不会再执行第二次刷新。

项目按下后必须超过 Windows 系统拖动阈值才进入 `DoDragDrop`，因此单击和双击启动不会被误判为拖出。数据源提供 `CF_HDROP` 和首选移动效果；拖到 Explorer 后按返回效果重新枚举源 Card，同一卡片内 Drop 则复用同一路径完成排序。取消拖动不改变文件和顺序。

图标规格和名称显隐属于每个 Card 的内容偏好，不属于全局渲染常量。设置入口由事项 23 的主界面提供；当前宿主与快照已经消费并持久化这两个值。

设置页提供自定义、名称、大小、项目类型和修改日期五种排序入口，默认使用自定义。自动排序只改变当前投影顺序并保留稀疏自定义槽位，切回自定义后恢复用户原有位置。设置页的展示图标只控制标题栏 Grid/List 切换入口是否显示；当前展示状态仍由标题栏入口切换，二者独立持久化。

List 展示把 Custom 稀疏槽位按原 `(row,column)` 顺序临时展平为连续单列，每个项目严格占一行；切回 Grid 后原槽位不变。Grid/List 切换复用现有项目和图标快照，不触发目录刷新。尺寸变化会移动并保存下方 8 DIP 堆叠链，但 follower 只改窗口坐标，不重绘内容。

文件 Card 的高度同时受实例最大行数和当前工作区可用高度约束。宿主优先为下方堆叠 Card 及 8 DIP 间距预留位置，再按完整 Grid/List 行确定当前 Card 的有效可见行数；其余项目在 Card 内滚动，不能把下方 Card 推出工作区。

自适应尺寸切换到任一自动排序时保留稀疏自定义布局的当前列数；从未形成自定义列宽时使用 4 列。自动排序只向下增加行数，不再按项目数量把全部项目横向铺成一行。

空的展开 Application Card 保留与当前图标档位一行相同的内容高度，并显示轻量圆角虚线框和“拖放文件至此”；它不生成占位项目或伪造图标。`WM_MOVING` 只处理移动交互，不再根据交叠面积主动切换显示器或 DPI。跨入不同缩放显示器后由 Windows Per-Monitor V2 发送 `WM_DPICHANGED`；宿主完整采用系统建议矩形、更新显示器/DPI 并重建位图。这样由系统跨屏滞回决定切换点，避免窗口尺寸变化反复触发自定义 50% 边界。

## Rendering And Cost

Shell 图标在目录枚举时按当前档位解析为 32、48、64 或 96 px 的预乘 Alpha 像素，Card 的多屏 Projection 和运行期项目快照共享同一像素所有权，不重复保存图标位图。当前版本在启动、外部拖出和档位切换时刷新；卡片内和卡片间移动优先使用内存增量更新。目录实时监听、增量失效和大目录缓存属于事项 27。
