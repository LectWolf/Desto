# Desto Delivery Roadmap

本路线用于表达整体交付进度。进度编号按阶段验收，而不是按提交、文件数量或功能数量递增；一个阶段可以持续多次对话和多个提交。

## Progress Rules

- 所有阶段固定使用 `（N/5）阶段名` 标记。
- 只有当前阶段的退出条件全部满足，下一次工作才进入后续编号。
- 阶段内发现底层缺口时继续保持原编号，不能用部分完成冒充阶段完成。
- Bug 修复、讨论和临时插入任务沿用其所属阶段；跨阶段问题按最早尚未满足的依赖阶段计算。
- 路线允许根据验证结果调整阶段内部顺序，但改变五阶段边界需要同步修改本文件并说明原因。

## （1/5）底层与运行骨架

目标：建立不依赖最终 UI 技术、可以独立验证的数据安全和 Windows 运行基础。

范围：

- Card、Workspace、Placement、显示器身份和 Projection 领域模型。
- 应用卡片、映射卡片、待办卡片的内容归属与删除语义。
- 原子配置、schema 迁移、未知字段保留、存储根迁移和文件操作回滚。
- Windows 显示器拓扑、DPI、拓扑变化监听和稳定身份恢复。
- 应用命令、状态变更结果和持久化调度的运行骨架。
- 单实例、启动、正常退出、异常恢复、日志和诊断信息基础。
- 无 UI 的端到端场景测试以及第一版性能基线工具。

已完成：

- Card 类型与删除预览。
- 应用卡片文件退回事务、映射目录唯一性和存储根迁移。
- 版本化 JSON 原子保存。
- 多显示器 WorkspaceLayout、断屏回退投影和 Windows 稳定显示器身份适配器。

退出条件：

- 无 UI 测试可以完成创建、修改、删除、保存、重启恢复 Card 和 Workspace。
- 可模拟显示器连接、断开、DPI 与工作区变化，持久化 Placement 不被临时拓扑破坏。
- 配置损坏、写入中断、文件移动失败和异常退出均有确定恢复结果。
- Debug 与 Release 自动测试通过，并记录空运行的内存、线程、启动时间和空闲唤醒基线。

## （2/5）UI 技术与桌面宿主

目标：通过等价原型和测量选定最终 UI/渲染技术以及 Windows 桌面窗口模型。

范围：

- 用相同 Card 数量、图标素材、显示器拓扑和动效实现候选原型。
- 比较原生 Win32/DirectComposition 路线与仍具现实可行性的 UI 框架路线。
- 验证每 Card 独立窗口和统一合成宿主等窗口模型。
- 验证桌面层级、同步显隐、启动无抢焦点、拖动缩放、透明效果和圆角。
- 验证多 DPI、多显示器、任务栏变化、全屏应用和虚拟桌面行为。
- 测量冷启动、空闲内存、典型内存、显隐提交、输入延迟和空闲 CPU。

退出条件：

- 候选原型使用同一基准场景完成可复现对比。
- 选定技术达到性能预算，或对未达标项目形成明确且被接受的取舍。
- UI 技术、渲染模型和桌面宿主通过 ADR 固化。
- 选定原型可以稳定展示多个 Card，并消费第 1 阶段的真实 Projection。

## （3/5）核心可用版本

目标：完成可以日常使用的 Desto MVP，而不是只展示界面的演示程序。

范围：

- Card 创建、编辑、移动、缩放、层级、展开收起、显隐和二次删除确认。
- 每实例外观、功能入口和行为设置；全局默认不覆盖实例明确选择。
- ApplicationCard 的文件接收、原生 Shell 名称、图标、快捷方式和商店应用身份。
- MappingCard 的目录实时映射、显式引用、反向修改策略和失效状态。
- TodoCard 的基本增删改、完成状态和持久化。
- 屏幕边缘、中心和 Card 间吸附，按 Ctrl 临时绕过吸附。
- 桌面触发显隐、托盘、设置窗口和可清除的快捷键配置。
- 文件存储路径选择、迁移和所有删除副作用说明。

退出条件：

- 三类 Card 的完整主流程均可在真实桌面使用并跨重启恢复。
- 多屏、拖放、删除、存储迁移、托盘退出和显隐没有数据损坏或残留进程。
- 所有用户可见入口具有空状态、错误状态和必要的键盘/辅助功能行为。
- 自动测试覆盖稳定领域接口，关键 Windows 集成具有可重复的集成测试或硬件测试说明。

## （4/5）稳定性、性能与体验打磨

目标：让 Desto 达到长期常驻工具所需的响应、资源和可靠性标准。

范围：

- 启动与显隐批量提交，消除逐个出现、层级闪烁和抢焦点。
- 全屏应用、桌面切换、Explorer 重启、锁屏、休眠和虚拟桌面策略。
- Shell 通知、文件监视、图标缓存失效和大目录增量更新。
- 隐藏状态真正停止渲染、动画、监视和无意义唤醒。
- 故障注入、长时间运行、频繁显隐、拓扑抖动和存储中断测试。
- 动效、视觉层级、主题、缩放、Reduced Motion 和交互细节。
- Empty、Typical、Heavy、Hidden 四个场景的持续性能基准。

退出条件：

- Empty 私有工作集不高于 30 MB，Typical 不高于 50 MB，或形成有测量依据的新预算。
- 稳定后的空闲 CPU 接近 0%，隐藏状态没有持续渲染或高频唤醒。
- 冷启动到稳定画面不高于 500 ms，同步显隐提交目标不高于 16 ms。
- 关键故障和生命周期场景通过自动化或重复手工验证，无已知数据损坏和残留进程问题。
- UI 在目标 Windows 版本、多屏和 DPI 场景下完成视觉验收。

## （5/5）安装、更新与发布

目标：交付普通用户可安装、可更新、可卸载和可诊断的正式版本。

范围：

- 确定安装技术、单文件安装入口、按用户安装目录和数据目录策略。
- 开机启动、升级保留配置、降级限制、卸载时用户数据选择。
- 更新源、更新通道、完整性校验、失败回滚和离线安装包。
- GitHub Actions 的 Debug/Release 测试、构建、打包和 Release 产物。
- 第三方许可证、版本信息、构建可追溯性和发布说明。
- 代码签名、崩溃转储和隐私策略；需要外部证书时明确列为发布输入。
- 首次运行、设置、恢复和问题诊断所需的最小用户文档。

退出条件：

- 干净 Windows 环境可通过一个安装包完成安装、启动、升级和卸载。
- GitHub Actions 可从带版本标签的提交重复产生相同结构的发布产物。
- 更新失败不会破坏当前可运行版本或用户配置。
- 发布清单、许可证、性能结果和已知限制齐全。
- 正式 Release 产物完成最终安装和日常使用验收。
