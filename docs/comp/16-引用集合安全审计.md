# 引用集合安全审计

状态：本轮已修复主要拖放与菜单风险；移动与 Ctrl 复制已使用显式事务并完成回滚测试。

审计范围：MappingCard 的 `References` 模式、文件项拖放、Windows Shell 右键菜单、卡片删除、来源切换、目录导航和跨卡片拖放。

## 结论

`References` 的领域模型本意是保存外部文件路径，不拥有源文件；但 Windows 宿主层把引用项目作为普通文件拖放源处理，导致 Explorer 或其他接收方可能执行真实移动。当前最严重的问题是：

1. `WindowsDesktopHost.cpp:3364` 对所有 Application/Mapping 文件项调用 `BeginFileDrag({item.sourcePath}, cardId)`，没有携带“这是引用、禁止修改源文件”的来源策略。
2. `WindowsFileDragDrop.cpp:547` 对所有拖出统一允许 `DROPEFFECT_MOVE | DROPEFFECT_COPY`。
3. `WindowsFileDragDrop.cpp:253-256` 对所有拖出统一写入 `Preferred DropEffect = DROPEFFECT_MOVE`。

旧版本中，引用文件拖到同一卷的 Explorer 目录时通常会被当成 MOVE。当前拖放源已携带显式 `allowMove` 策略：References 根项目只允许 COPY；引用根目录拖出改为移除映射确认；进入引用目录后才允许直接操作其中的真实文件。

| 操作 | References 当前行为 | 是否修改外部源文件 | 风险 |
|---|---|---:|---|
| 从 Explorer 拖入 References | `SetMappingReferences`，只增加绝对路径 | 否 | 低 |
| References 内同卡片拖动 | 仅更新自定义槽位 | 否 | 低 |

## Folder Mapping 与 Application 的边界

以下是当前设计中**有意允许**修改源文件的路径，不能与 References 的只读引用语义混在一起：

- Folder Mapping 有来源且 `allowsSourceMutation=true`：外部拖入会通过 `DirectoryImportPlanner` 和 `FileMoveTransaction` 移入来源目录；失败时回滚已完成移动。
- Folder Mapping 文件改名：需在资源管理器中完成，目录监听随后刷新卡片。
- Application Card：卡片拥有自己的管理目录；外部拖入和卡片内整理可移动到管理目录，删除卡片时受确认流程约束并将受管文件退回桌面。

这些能力需要在 UI 中明确标示“会移动文件”，不能因为目标卡片是 Mapping 就默认推断来源项目允许被修改。

## 配置兼容风险

- 新建 Mapping 在 `apps/DesktopHostMain.cpp:1471-1473` 设置 `allowsSourceMutation=false`。
- 旧配置缺少该字段时现在按来源模式推导：References 为 `false`，Folder 为 `true`（`src/storage/JsonConfigStore.cpp`）。
- `MappingCard` 领域默认值仍为 `true`，但新建 Mapping 会立即写入 `false`，并且 References 的根项目不再允许源文件变更。

旧版 References 配置缺字段时不会再继承源文件变更权限；Folder 才能保留用户明确选择的可写策略。

## 其他数据一致性风险

- `FileMoveTransaction` 在跨卷移动失败时使用“复制后 `remove_all(source)`”作为回退。复制或删除阶段、以及后续回滚阶段任一失败，都可能留下源与目标同时存在或仅剩目标的半完成状态；诊断会记录失败，但当前没有用户可恢复的事务日志。
- Folder Mapping 导入现在在 `SaveRuntimeConfiguration` 成功后才释放移动回滚保护；保存失败会恢复布局并由保护回滚已移动文件。这不影响 References 的拖出根因，但跨卷复制/删除失败仍需后续专项事务日志。
- Application Card 导入、删除退回桌面和存储根迁移同样依赖文件移动后回滚；回滚失败只进入诊断日志，不能保证用户文件恢复原位。

## 当前测试缺口

`desto_windows_file_drag_drop_tests` 已增加 copy-only 数据对象断言；`WindowsDesktopHostTests` 仍未覆盖真实鼠标拖出引用根目录的确认流程，需要后续桌面集成测试。

## 建议修复顺序

1. References 根项目继续只报告 `DROPEFFECT_COPY`，Preferred Effect 也只能是 COPY。
2. 目标决策同时检查来源策略和 Ctrl 状态；普通 MOVE 与 Ctrl COPY 必须调用对应事务，不能只改变光标。
3. References 禁止通过 Desto 菜单重命名外部源文件；需要改名时使用资源管理器。
4. References 的紧凑和经典菜单都拦截 `cut`、`delete` 等源文件变更动词；“显示更多选项”也应使用受限菜单或明确风险确认。
5. 已增加回归测试：OLE keyState 传递、复制效果、源保留、目录递归复制和批次失败回滚。
