# 问题登记与评估重点

严重度：P0=数据损坏/无法恢复；P1=核心桌面或发布阻断；P2=明显行为不一致或未验证风险；P3=体验/文档改进。

## 设计/安全风险

| 编号 | 严重度 | 风险 |
|---|---|---|
| COMP-014 | P1 | 主程序根许可证和代码签名证书仍是外部输入；不能用仓库占位符伪造发布合规 |
| COMP-015 | P2 | Card 主要依赖鼠标；键盘导航、屏幕阅读器、触摸/高对比度未形成独立验收证据 |
| COMP-016 | P2 | Application/Mapping 文件归属与引用语义复杂；失败提示必须把实际副作用说清，不能只显示通用“操作失败” |
| COMP-017 | P3 | 文档中的 `Content Density`、`Card Width Policy` 与实际文件卡片外宽公式仍有命名耦合，容易让设置动作误解为改图标尺寸 |

## 建议的最小修复顺序

1. 统一 CTest/RC 文档和性能报告口径。
2. 进行真实双屏、任务栏恢复、Explorer 生命周期、拖放滞回和设置层级验收。
3. 再决定全局圆角是否改为默认值而非批量覆盖。
4. 发布前补齐根许可证和签名证书，并重跑不含扩展 payload 的安装/发布验证。
