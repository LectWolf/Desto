# 映射导航与引用删除

## 导航状态

映射卡片的文件夹浏览属于进程会话，不属于 `MappingCard` 持久模型。应用层用 Card ID 关联目录路径栈；路径栈非空时，Card 标题显示栈顶目录名称，项目来自该目录的直接枚举，标题左侧显示向上按钮。双击文件仍调用 Shell；双击文件夹将路径压栈并刷新同一 HWND，不创建新的 Card 或 Explorer 窗口。

Folder 来源的根内容就是边界，返回到空栈后恢复来源根枚举。References 的根是原引用集合，任何顶层文件夹引用都可以作为第一层；空栈时恢复 Card 的用户标题、原项目、自定义排序和绝对路径 Placement。导航层项目不套用根集合的稀疏 Placement，并把滚动重置到首行。

标题向上按钮为 36 DIP 命中区，位于标题左侧 6 DIP 内边距。按钮存在时标题起点移至按钮右侧再加 4 DIP；按钮具有独立 hover、pressed、capture cancel 和 `HTCLIENT` 命中，避免按下时发起 Card 拖动。

## 删除语义

References 不拥有源文件。紧凑菜单把 Delete 文案替换为“移除引用”，直接通过 Card ID 与项目绝对路径调用应用回调；确认使用 Desto 自绘模态面板，不调用系统 `MessageBox`。根文件夹只有实际拖出 Desto 后才进入同一确认流程，卡片内拖动仅更新自定义槽位。经典 `IContextMenu` 仍完整显示文件菜单，但选中 canonical `delete` 时由宿主拦截，不执行 `InvokeCommand`。

应用回调删除匹配路径的 `FileReference`，用剩余项目协调 Mapping Placement，更新桌面和设置 CardView，并原子保存配置。Folder 与 Application 不走该回调，保留文件自身的 Windows 删除语义。

## 成本与失败处理

路径栈只在进入文件夹后分配。返回根、切换 Mapping 来源或删除 Card 时释放。目录枚举失败保持当前来源与配置不变并记录诊断；导航状态不会让 Folder 额外持有目录监视句柄。
