# 存储、配置与迁移

## 目录

- 默认程序：`%LocalAppData%\Programs\Desto`。
- 默认数据：`%LocalAppData%\Desto`。
- 主配置：数据根父目录下 `settings.json`（实际启动逻辑以 `DefaultStorageRoot()` 为准）。
- Application Card：storage root 下的相对卡片目录。
- 首次启动不预建 Card 子目录或 Mapping preview；Application 目录在用户明确创建对应 Card 后按需生成。

`StorageRoot::resolveCardPath` 负责把相对 Card 路径限制在根目录内；领域和 JSON 不应保存 Application 绝对路径。

## schema 27 顶层

```text
schemaVersion
storage.root
settings
cards[]
workspace.placements[]
```

### settings

`language`、nullable `timeZoneOffsetMinutes`、`globalCardCornerRadius`、`runAtStartup`、`desktopDoubleClickAction`、`taskbarDoubleClickAction`、`pinnedCardsYieldToFullscreen`、`showIconBackgroundFrame`、`cardOrder[]`。旧配置中的 `restoreWindowsOnNewWindow` 仅为无行为的兼容字段，会原样保留但不再提供界面入口。

### Card 通用 JSON

`id/name/type/visible/expanded`；`chrome` 保存 showCollapseControl/showCloseControl/showPinControl/showPresentationControl/pinOnTop/showTitle/positionLocked 七个布尔字段；`appearance` 保存 preset/opacity/cornerRadius；`content` 保存 itemSize/showItemNames/sizeMode/widthSpan/fixedColumns/fixedRows/maximumVisibleRows。

类型对象：

- `application`: storagePath、sortMode、presentationMode、itemPlacements(fileName,column,row)。
- `mapping`: allowsSourceMutation、sourceMode、presentationMode、sortMode、itemPlacements(path,column,row)，以及 sourceRoot 或 references(id,path)。
- `todo`: showCreatedTime、items(id,title,completed,createdAt,completedAt,archived,scheduledDate)。

### Placement JSON

保存 id、cardId、target(kind,displayId)、rect(left,top,width,height)、zIndex、horizontalAnchor、verticalAnchor、referenceWorkArea(width,height)。未知字段在同 id 节点上保留。

## 迁移

显式链从 v1 到 v27，禁止跳猜。关键节点：v2 cards；v3 content/item order；v4 稀疏槽位；v5 anchor/reference work area；随后 Todo、Mapping 和系统设置；v18 图标背景框；v19 从 fixedColumns 推断密度无关 widthSpan；v20 `transparent-black` 迁移为 `transparent-white`；v21 cardOrder；v22 Application presentationMode + Mapping 绝对路径槽位；v23 删除旧扩展 Card、对应 Placement、cardOrder 项、disabledExtensions 和 valueAnimation；v24 增加 showPresentationControl、把 Todo 3/4/5 档映射为 4/5/6，并将非 Right 水平锚点归一为 Left；v25/v26 分别把 `transparent-white` 的已知旧内置 opacity 0.36/0.62 改为 0.32，其他实例值不变；v27 为旧 Card 增加默认关闭的 positionLocked。迁移保留内置 Card 与未知字段，并有 schema 22 至 26 的定向 fixture 覆盖。

未来版本抛 `UnsupportedSchemaError`，不会回退旧备份，防止旧程序覆盖新格式。旧版本逐步迁移到 27 后再验证 Card/Placement 约束。

## 原子写入与备份

1. 读取当前 JSON 并迁移；保存时保留未知字段。
2. 首次覆盖前复制当前文件为 `settings.json.bak`（除非本次加载已从 backup 恢复）。
3. 在同目录创建唯一 `.tmp-<timestamp>`。
4. Windows 使用独占 `CreateFileW(CREATE_NEW)`、`WriteFile`、`FlushFileBuffers`。
5. 已有目标用 `ReplaceFileW(REPLACEFILE_WRITE_THROUGH)`；首次发布用 `MoveFileExW(WRITE_THROUGH|REPLACE_EXISTING)`。
6. 任意异常删除临时文件并保留最后有效配置。

加载主文件失败、损坏或缺失时尝试 `.bak` 并设置 `recoveredFromBackup=true`。未来 schema 错误例外，不允许备份降级。

## 文件移动事务

`FileMoveTransaction` 接受显式 source/destination 列表。同卷优先重命名；跨卷复制后校验并删除源；任何一项失败时从已完成列表逆向 rollback。失败结果保留 completedMoves 和 failures，不能静默吞错。

文件项重命名不属于 Desto 存储事务；由资源管理器执行，Desto 通过目录监听或手动刷新重新枚举源目录。

用途：

- Application import：外部来源 -> Card 管理目录。
- Card transfer：源 Card 目录 -> 目标 Card 目录。
- Application delete：Card 管理目录 -> Desktop，必须确认 CardId。
- Mapping Folder import：外部来源 -> 映射源目录，仅允许可变来源。
- Storage root migration：列出所有根内容，事务迁移，再发布新配置；配置发布失败时反向恢复文件。

目标冲突必须在 plan 阶段生成不覆盖的名称。嵌套来源、来源等于目标、重复目标、越界根目录和锁文件均需明确失败。

## 诊断与隐私

日志等级和生命周期诊断由 `application/Diagnostics` 统一管理；用户路径内容不应直接进入面向用户消息。设置页只显示简洁失败提示，具体错误码进入诊断。异常退出不能在退出路径再次覆盖最后有效配置。
