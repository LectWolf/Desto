# 窗口交互与系统集成

## Card 窗口

正式 Card 是无激活、工具型、分层 Win32 窗口；启动和批量显隐使用无激活提交，避免逐窗抢焦点。普通 Card 绑定 Explorer 桌面 owner，使其位于桌面层；置顶实例使用 TOPMOST，但“全屏让位”开启时检测到全屏应用会隐藏。

窗口绘制使用离屏 DIB；完整提交与 dirty-region 提交分别统计。创建、销毁、DPI 变化或尺寸变化时重建位图和缓存字体。图标和背景使用预乘 Alpha；tooltip 是独立 topmost 小窗口。分层 Card DIB 禁止 ClearType RGB 子像素覆盖，GDI 使用灰阶抗锯齿，彩色 Emoji 与 `WindowsTextInput` 的 DirectWrite RenderTarget 显式设置灰阶文字抗锯齿；Tooltip 和设置主窗口是不透明目标。

## 拖动与吸附

拖动从标题非控件区域进入系统 move loop。`ResolvePlacementInteraction` 的约束：

- 安全边距 8 DIP；无论 Ctrl 是否按下都保留工作区夹取。
- 吸附搜索距离 12 DIP。
- 优先匹配屏幕左/中/右、上/中/下以及其他 Card 的等距关系。
- Ctrl 绕过吸附，但不绕过工作区安全夹取。
- 水平锚点默认 Left；只有 Card 右边缘吸附屏幕右安全线或与另一 Card 右边缘对齐时保存 Right。中心线、左边缘、普通位置和 Ctrl 绕过均保存 Left。
- 吸附指示线为 3 DIP 透明虚线，仅拖动时按需创建；dash 11 px、gap 7 px（具体像素绘制）。
- 同屏卡片若水平左/右/中心对齐、垂直相距 8 DIP（容差 1.5）则形成纵向堆叠；每个 Surface 的 Layered Window 提交记录 `lastCommittedVisibleHeightDip`，提交后检测到高度变化就统一移动下方链并保存 Placement。收缩/展开、日历、内容更新、输入状态和 Grid/List 不再各自补重排事件。

Placement 比较容差 0.01 DIP；堆叠几何容差 1.5 DIP。跨屏时 `WM_MOVING` 保持当前像素尺寸，不按最大交叠面积主动切屏；Windows Per-Monitor V2 的 `WM_DPICHANGED` 到达后完整采用系统建议矩形，更新 display/DPI 并重建位图。落下后提交 display id、DIP rect、anchor 和 reference work area。

堆叠重排只改变 follower 的 `projection.rect.top`，并以 `SetWindowPos(SWP_NOSIZE|SWP_NOZORDER|SWP_NOACTIVATE)` 移动现有 HWND。它不会重新枚举文件、解析图标、分配位图、重绘 follower 或再次调用 `UpdateLayeredWindow`；每个实际移动的 follower 只发送一次 Placement 回调。上方 Card 自身仍按交互需要绘制：例如 collapse 按下态和完成态各一次整面提交，不能把这两次自身反馈误判为下方内容刷新。

内容驱动测量会先为完整 follower 链预留可见高度和每级 8 DIP 间距，再从 Grid/List 的完整行中选出当前 Card 可容纳的最大行数。下方 Card 的占位优先于上方 Card 展示全部项目；被截断的项目通过上方 Card 自身滚动访问，而不是把 follower 推出工作区。

文件拖放的自适应边缘扩展不属于用户拖动 Card，也不重新判定 anchor。宿主把预览前 rect 单独保存在 surface：预览只提交 HWND；成功落下后的同步内容更新才比较原 rect 与最终 rect，并通过 `PlacementChangedCallback` 写回 Runtime。Right anchor 的最终 rect 同时改变 `left` 和 `width` 以固定右边缘；Left 固定 `left`；所有垂直 anchor 固定 `top`。取消或失败必须恢复预览前 rect，不能让 Center/Bottom 的常规重排逻辑消费临时预览尺寸。

拖放命中使用当前 HWND 的 DIP 宽度和当前客户区指针坐标。每次扩列后，Left 卡片的下一条扩展线随新右边缘移动，静止指针不会跨过下一条线；Right 卡片因右边缘不移动而继续使用逐次增加的阻尼。收缩每次最多一列并等待 200 ms，重新进入当前列区域取消；Right 卡片收缩时仍以预览前右边缘为基准，同时增加 `left`、减少 `width`。

官方依据：Microsoft 的 [`WM_DPICHANGED`](https://learn.microsoft.com/windows/win32/hidpi/wm-dpichanged) 文档要求使用 `lParam` 中的建议矩形重新定位和调整窗口；[High DPI Desktop Application Development on Windows](https://learn.microsoft.com/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows) 说明 Per-Monitor V2 由系统发送顶层/子窗口 DPI 通知。Desto 因此不再实现基于 50% 交叠的第二套切换阈值；跨屏切换点和滞回由 Windows 决定。

## Placement 与显示器

DisplaySnapshot：稳定 id、工作区原点/尺寸、effective DPI、primary。生产身份来自 Windows monitor device path，不使用枚举序号。

Placement：id、cardId、target、DIP rect、zIndex、水平/垂直锚点、参考工作区尺寸。规则：

- rect 所有数值有限且 width/height > 0。
- reference work area 要么宽高都缺失（0），要么均为正有限值。
- 同 Card 每个具体显示器最多一个 Placement；AllDisplays 不能和具体显示器混用。
- 离线具体显示器不产生 projection，也不回退到主屏；Placement 保留并由 `unavailablePlacements()` 返回。
- AllDisplays 按显示器 id 排序生成 projection。
- 工作区变化时 Left/Top 保持起始边距，Right/Bottom 保持末端边距，Center 保持中心偏移，Free 按可移动范围比例重排；最终 projection 夹进工作区，但不改写持久 Placement。
- 上述工作区重排规则不覆盖拖放扩展方向；拖放扩展使用预览前 rect，最终成功时显式写回新的 Placement rect。

## Z-order 与桌面层级

- 设置窗口必须在 Card 之上；Card 拖动时可以临时位于 overlay 之下/桌面之上，结束后修复层级。
- 普通 Card 的 owner 在 Explorer 重启后重新发现；置顶 Card 在前台窗口事件后重新确认 TOPMOST。
- 锁屏、休眠、错误虚拟桌面或全屏让位状态阻止 Card 显示；恢复时只批量切换可见状态，不重新洗牌 z-order。
- 纵向堆叠关系从 Placement 和完整展开尺寸重建，不持久化 HWND 链。

## 桌面与任务栏双击

桌面背景双击检测使用系统 `GetDoubleClickTime`、`SM_CXDOUBLECLK`、`SM_CYDOUBLECLK`，只接受桌面背景点击。配置值：

- desktop 默认 `all`，另有禁用/图标/Card 联动组合（设置页提供 4 个选项）。
- taskbar 默认 `none`，另有 `current-display` 和全部屏幕（3 个选项）。
- taskbar 为 `none` 时强制 `restoreWindowsOnNewWindow=false`。

任务栏命中先确认根窗口为 `Shell_TrayWnd` 或 `Shell_SecondaryTrayWnd`，再用 `ChildWindowFromPointEx/RealChildWindowFromPoint` 获取任务栏子窗口。Windows 11 的组合/XAML 覆盖层会继续通过 UI Automation `ElementFromPoint` 判定当前点的控件类型：按钮、分割按钮、编辑框、列表项、菜单项和选项卡一律拒绝；只有当前点成功识别为中性容器（Pane、Toolbar、Window、Custom）时才视为空白。UI Automation 查询失败、未知窗口层级和辅助功能查询失败均拒绝，不能把任务栏根 HWND 本身当作放行条件。

全部屏幕模式调用 Explorer 原生 Show Desktop；当前屏幕模式枚举 HMONITOR 上的窗口并保存 top-to-bottom 顺序及 `WINDOWPLACEMENT`。恢复时 `SW_SHOWNOACTIVATE`，按原链重建 z-order，最后激活原前台窗口。普通手动最小化不属于捕获会话。

`restoreWindowsOnNewWindow` 是实验设置：会话期间出现新的前台窗口时先恢复捕获窗口，再把新窗口放回最上层。关闭设置则只在再次双击时恢复。

## 托盘与启动

- 托盘注册 `NIF_MESSAGE | NIF_ICON | NIF_TIP | NIF_SHOWTIP`，`szTip` 固定为 `Desto`；在 `NOTIFYICON_VERSION_4` 下仍明确显示悬浮名称。
- 托盘使用原生 `HMENU/TrackPopupMenuEx`，菜单含打开设置、显示/隐藏桌面 Card、退出；语言支持 system/zh-CN/en-US。
- 原生菜单由 Windows 负责字体、DPI、快捷键列、深浅主题和禁用状态，不使用 owner-draw。文件项在 Win11 默认策略下显示来自 `IContextMenu` 的紧凑核心动词与“显示更多选项”；经典覆盖或旧系统直接进入完整菜单。Explorer XAML 菜单无公开外部 HWND 托管接口。
- 开机启动优先创建根目录任务 `Desto`：`TASK_TRIGGER_LOGON`、Delay 空、Interactive Token、LUA、动作参数 `--autostart`、工作目录为 exe 目录。任务成功后删除旧 Run 值。
- 当前用户无计划任务写权限时回退 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，记录固定诊断码；不设置影响全部启动应用的 `StartupDelayInMSec`。关闭与卸载同时尝试删除任务和 Run 值。
- 启动参数：显示设置、自动启动标志、可选 duration milliseconds（测试退出）。
- 启动时把任务/回退状态与持久偏好对账；保存失败时回滚启动注册并写诊断。
- 单实例 gate 阻止第二个常驻进程；生命周期状态为 Created/Starting/Running/Stopping/Stopped/Faulted。

首次不存在 `settings.json` 与 `.bak` 时，启动只向空 Runtime 提交当前 DisplaySnapshot 并保存空 cards/workspace；不生成示例 Card、Placement 或 Mapping 临时目录。已有配置继续按 schema 恢复，不以“空 Card 列表”误判为首次启动。

## 文件项操作

文件项右键通过 `IContextMenu` 执行 Explorer 原生命令。Desto 不提供文件项重命名入口；文件夹的“打开”命令交给资源管理器处理。需要改名时，用户在资源管理器中完成操作，目录监听或手动刷新随后更新卡片。

## Explorer 与 Shell 生命周期

隐藏生命周期窗口处理 `TaskbarCreated`、session lock/unlock、电源 resume。桌面 owner 不可用时每 250 ms 重试；修复 owner 不应重建 Card HWND。图标显示/隐藏通过 Explorer 桌面 ListView；桌面 Card 与桌面图标可独立或同步切换。

桌面/任务栏双击仍使用 `WH_MOUSE_LL`，但 Hook 安装在独立消息线程。Hook 回调对所有非左键事件直接 `CallNextHookEx`，左键只把坐标和时间戳 `PostMessage` 到 UI 隐藏窗口；桌面、任务栏、Accessibility 命中和用户回调全部在 UI 线程执行。析构通过 `WM_QUIT` 停止线程并 join，不轮询、不在 Hook 回调访问 Explorer，也不让 Card 的同步渲染阻塞系统全局鼠标 Hook 链。任务栏会话快照统一排除所有 `Desto*` 顶层窗口，设置页和输入 Popup 不会被外部窗口恢复逻辑捕获。

## 可访问性与输入

系统数据存储位置迁移使用设置窗口自绘确认层，不调用 `MessageBox`。选择目录后先保留目标路径为待确认状态，遮罩层提供取消/迁移按钮；确认后才调用 `StorageRootMigrationService`，失败由应用层回滚并保留原存储根。Escape 和外部点击不会执行迁移。

- 设置页支持键盘焦点序列、统一自绘 `WindowsTextInput` 和本地化；图标按钮在 Windows 11 优先使用 `Segoe Fluent Icons`，Windows 10 缺少该字体时自动回退系统 `Segoe MDL2 Assets`。字体选择由共享适配器缓存，设置页、桌面 Card 和输入框不再各自硬编码字体。归档日期标签在同一焦点链，自绘日历先消费 Escape，再由设置窗口执行隐藏；日历显示时隐藏搜索输入子窗口，关闭时恢复，保证子 HWND 不会压住父窗口绘制的浮层。
- 当前 Card 本体主要以鼠标/拖放操作，完整键盘导航和屏幕阅读器行为没有独立人工验收记录，应在问题清单中继续跟踪。
