# 已撤销的扩展与工资卡原型

## 当前结论

Extension Card、`ICardExtension`、扩展注册表、包加载器、`.desto-extension`、原生 DLL C ABI、通用扩展设置字段、工资示例、动态数字转场和时间驱动刷新均已从当前产品撤销。它们不再是可调用接口、可构建目标、设置入口、安装内容或发布资产。

## 已删除范围

- 领域：`CardType::Extension`、`ExtensionCard`、扩展快照字段、`DynamicValueAnimation`。
- 应用：`CreateExtensionCard`、`SetExtensionCardState`、扩展恢复和状态命令。
- 展示：扩展内容树、扩展布局、Number 节点、滚动/跳变转场。
- Windows 宿主：扩展渲染分支、金额字体和背景缓存、动画 timer、业务 deadline、时间刷新 callback、专用 dirty-region 统计。
- 设置：扩展目录页、安装/启停/删除、添加扩展 Card、扩展字段编辑器、数值动画和宽度特殊入口。
- 包与 SDK：manifest、C ABI 头、加载器、注册表、工资 DLL、示例包、许可附加文件和 SDK 文档。
- 工程：CMake 目标、单元测试、工资性能门禁、安装器 payload、发布 zip、CI 上传和第三方 PayDance 声明。

旧 `build` 缓存中的扩展 DLL、测试 exe/obj、工资门禁工程和旧发布校验目录也已按明确路径移入回收站；重新运行 CMake 后不再生成这些目标。源码根、`src` 和 `tests` 下的空 `extensions` 目录已删除。

## 兼容启动

schema 23 不尝试执行或解释旧扩展 state。加载 schema 22 时，它收集 `type == "extension"` 的 Card ID，删除这些 Card 及引用它们的 Placement 和 `settings.cardOrder` 项，同时删除 `settings.disabledExtensions` 和保留 Card `content.valueAnimation`。迁移后只验证和恢复内置 Card，避免已卸载代码因未知类型阻止启动。

该迁移是有意的数据丢弃：旧扩展私有 state 不转成内置 Card，也不保留悬空 Placement。`settings.json.bak` 仍受通用备份策略保护；当前程序继续迁移到 schema 27 后也不会重新生成旧扩展对象。

## 重新规划门槛

未来若重新引入扩展，必须新建原型和 ADR，重新确定隔离边界、权限模型、崩溃恢复、资源预算、内容布局、交互节流、版本迁移、签名和发布合规。旧 API 1、旧 manifest 和旧工资基准均不构成兼容承诺。
